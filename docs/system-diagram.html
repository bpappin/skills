Issues — work (canonical)

Epics → stories. Each story: narrative, ## Acceptance Criteria checklist (= the scope), optional ## QA Gherkin. Discovered work = new issue, linked discovered from.

Knowledge base — knowledge (owns structure)

Sections are top-level articles; a section article's body doubles as its filing guide (it becomes the directory's README.md). Move or rename an article and the repo tree follows on the next sync. Conflicting edits get git markers locally — never force-pushed either way.

The session loop: yt-sync (fresh mirror) → set_focus → get_story_context (the AC list is the scope) → work → update_ac as items verifiably finish → anything out of scope takes the add_discovered_work off-ramp and you return to the story → doc edits sync back article-by-article as they happen → complete_story gates closing (all AC checked; QA section if needs-gherkin). Skills ride in the repo (.agents/skills/); credentials stay per-user; the pointer file binds repo → instance.
